# afford.today — техническая спецификация MVP

## v0.3 — актуальная механика (заменяет разделы 2–10 ниже)

Старое MVP превращало разрешение в награду за очки и полезные дела. Это противоречило самой идее
продукта и делало первый сценарий непонятным. Начиная с v0.3 ядро такое:

1. Человек добавляет покупку или действие/время для себя. Для покупки доступны ссылка и цена; для
   действия достаточно фразы вроде «полежать 15 минут без вины».
2. Покупка получает три финансовые опоры: обязательные расходы, отсутствие долга и настоящее
   желание. Действие получает три подходящие опоры: безопасность, наличие времени и желание.
3. При желании называет внутренний стоп-сигнал: жалко денег, «не заслужил», страх пожалеть или
   привычку сначала быть полезным.
4. Сам выбирает «мне можно» или «отложить». Приложение помогает увидеть решение, но не выносит
   финансовый вердикт. «Отложить» сохраняется как настоящее решение (`postponedAt`), отмечается в
   карточке и не закрывает возможность вернуться позже.
5. После покупки или действия можно отметить ощущение. Экран «доказательства» считает принятые решения и сферы,
   в которых человек начал доверять себе; потраченная сумма не называется свободой.

В ядре нет очков, порогов, домашних заданий, гринда, нескольких вишлистов и платного ограничения
основного сценария. Поля и API старой механики временно сохраняются только для совместимости данных.
На одно желание создаётся не более одного `PermissionEvent`: при «мне можно» он появляется с нулевой
стоимостью, а после отметки о покупке дополняется ценой.

**Главная продуктовая метрика:** доля пользователей, которые добавили покупку и приняли решение.
Вторичные: доля «мне можно», отметок о покупке и check-in. Аналитика агрегатная, без PII.
Счётчики событий и текущие состояния желаний доступны владельцу через защищённый
`GET /api/admin/product-metrics` с `CRON_SECRET`.

> Остальная часть документа — историческая спецификация v0.2. Она не является источником истины для
> новых экранов и механик.

> Документ для разработки (в т.ч. как контекст для Claude Code). Можно положить в репозиторий как `SPEC.md`.
> Принцип всего ниже: **психология — это движок под капотом, наружу не торчит**. Пользователь нигде не видит слов «травма / критик / дефицит». Поверхность — лёгкий, чуть нахальный продукт.

## 0. Что это

Telegram Mini App, который выдаёт человеку разрешение спокойно тратить на себя. Аудитория — те, у кого деньги есть, но есть внутренний запрет тратить их на себя. Продукт ловит момент желания, помогает дойти до «Можно!» и копит доказательства того, сколько человек себе уже позволил.

**Северная звезда:** не время в приложении, а число спокойных трат на себя. Хороший исход — человек со временем разрешает себе **сам**, без приложения.

---

## 1. Сквозные принципы (важно для всех экранов)

1. **Никогда не блокируем покупку.** Кнопка «уже купил(а)» доступна всегда. Обойти порог — это не читерство, это праздуется.
2. **Ноль стыда.** Нет «ты сорвал стрик», нет красных предупреждений, нет вины. Пропуск — нейтрально.
3. **Базовое — без порога.** Еда, лекарства, гигиена открываются мгновенно.
4. **Тон — нахальный друг.** «Да заслужил уже, бери», а не коуч и не терапевт.
5. **Приватность.** Из PII — только telegram_id. Заметки и ощущения никогда не уходят в маркетинг и шеринг.

## 2. Модель данных

```

  currency               (ISO, напр. "RUB", "USD" — для отображения)
  locale
  subscription_status    (free | active | expired)
  gifted_tokens          (int, «подаренные разрешения»)
  settings               (json: notifications_enabled, nudge_time, theme)

Wish                     // желание / цель
  id                     (PK)

  title
  image_url              (nullable; подтягивается из ссылки)
  source_url             (nullable; ссылка на товар)
  price                  (decimal, nullable)
  currency
  type                   (essential | need | want)
  domain                 (clothes | leisure | comfort | health | joy | food | other)
  points_required        (int; вычисляется при создании, см. §4)
  points_earned          (int, default 0)
  status                 (active | unlocked | purchased | archived)
  created_at
  unlocked_at            (nullable)
  purchased_at           (nullable)

Step                     // шаг к цели / челлендж
  id                     (PK)
  user_id                (FK)
  wish_id                (FK, nullable — null = отдельное микро-разрешение)
  title
  kind                   (step | micro_permission)
  points                 (int)
  done                   (bool, default false)
  done_at                (nullable)

CheckIn                  // отметка после покупки
  id                     (PK)
  wish_id                (FK)
  feeling               (enum, см. §7)
  note                   (text, nullable, приватно)
  created_at

PermissionEvent          // питает карту и «счёт свободы»; пишется при каждом «разрешил себе»
  id                     (PK)
  user_id                (FK)
  wish_id                (FK, nullable)
  value                  (decimal — сумма траты на себя; 0 для нетоварных микро-разрешений)
```

Карта и вся статистика — **производные** от `PermissionEvent` + `Wish`, отдельно не хранятся.

## 3. Механики — полное описание

### 3.1 Вишлист (желания)
- Пользователь добавляет вещь: название, цена, картинка. Если кинул ссылку — парсим OG-теги (`og:image`, `og:title`, мета-цену) на бэкенде и предзаполняем.
- При создании выбирается **тип**: «нужное», «хотелка» или система сама предлагает «это базовое?» для еды/лекарств.
- Тип определяет порог (§4) и домен карты.
- Ощущение — Pinterest × копилка. Это аспирационный, приятный экран без всякой терапии.

### 3.2 Типы и домены
- `essential` — еда, лекарства, гигиена. `points_required = 0`, разблокировано сразу. Экран говорит «это бери сразу, без вопросов».
- `need` — нужное, но не критичное. Символический порог.
- `want` — хотелка. Порог растёт с ценой.
- `domain` — для карты освобождения (§8). Подсказывается по типу/названию, редактируется.

### 3.3 Шаги и челленджи
- К цели можно добавить шаги (`kind = step`) — что угодно, что человек считает своим продвижением. Каждому — размер → очки.
- Плюс «микро-разрешения» (`kind = micro_permission`) — маленькие приятные челленджи из библиотеки («позволь себе кофе навынос», «возьми такси, не жди автобус»). Они либо стоят отдельно, либо капают очки в активную цель.
- При пустом списке показываем 3–4 готовых предложения, чтобы убить страх чистого листа.

### 3.4 Очки и шкала (конкретика)
- Размеры шага → очки: **мелкий = 10, средний = 25, крупный = 50.** По умолчанию средний.
- Микро-разрешение по умолчанию = **15.**
- Шкала цели заполняется по мере `points_earned`. При `points_earned >= points_required` → `status = unlocked`.

### 3.5 Момент «Можно!» (ядро продукта)
- Триггерится при разблокировке (или при тапе «уже купил»).
- Полноэкранно: конфетти/анимация, тёплая нахальная фраза, картинка вещи, кнопка «Поделиться» → генерит шар-карточку (§9).
- Пишет `PermissionEvent`. Если разблокировали раньше порога — `below_threshold = true`.
- В этот экран вкладываем максимум полировки: это и дофамин, и вирусный двигатель.

### 3.6 «Тающий порог» (мышца самоподдержки)
- Каждый раз, когда пользователь помечает покупку при `points_earned < points_required` (разрешил себе сам, не догриндив) → инкремент счётчика и **снижение будущих порогов `want` на 5%** (с полом, напр. не ниже 40% базового тира).
- Это механика «выпускника»: продукт мягко делает себя менее нужным. Можно вынести за MVP, но заложить поле в модель.

### 3.7 Подаренное разрешение
- Иногда приложение дарит `gifted_token` — разрешение без всякого гринда («это от нас, просто так»). Моделирует «не всё надо выслуживать».
- Удобно ложится на механику подарков Telegram, но в MVP — просто внутренний счётчик.

## 4. Расчёт порога (points_required)

MVP — простые тиры по цене (никаких пугающих формул). Брекеты задаются в валюте пользователя, дефолты конфигурируемы.

| Тип | Условие | points_required |
|---|---|---|
| essential | — | 0 |
| need | любая цена | 20 |
| want | дешёвая (ниже T1) | 100 |
| want | средняя (T1–T2) | 300 |
| want | дорогая (выше T2) | 800 |

Дефолтные брекеты (пример для RUB): `T1 = 3 000`, `T2 = 30 000`. Для других валют — конвертировать или дать пользователю задать «что для меня дорого». После «тающего порога» (§3.6) итог = `базовый_тир × множитель`.

## 5. Экраны

1. **Онбординг** (3 шага, §10) — заканчивается **немедленным маленьким разрешением себе**.
2. **Главный** — активные желания со шкалами; кнопка «+ хочу».
3. **Добавить желание** — название/ссылка/цена/тип; авто-картинка; авто-порог.
4. **Карточка желания** — шкала, список шагов, кнопки «выполнил шаг», «уже купил».
5. **«Можно!»** — разблокировка + шеринг.
6. **Чек-ин после покупки** — реакция в один тап (+ необяз. строка).
7. **Карта / Список да** — §8.
8. **Профиль/настройки** — валюта, уведомления, тема, подписка.

Для каждого экрана заложить состояния: пустое / загрузка / заполнено / офлайн.

---

## 6. Бот-компаньон

- Лёгкие, опциональные, с частотным капом, **без вины** пуши:
  - дневной нудж, если есть активная цель с невыполненными шагами;
  - поздравление с разблокировкой;
  - периодическое «ты ничего себе не позволял на этой неделе — давай мелочь?»;
  - сюрприз с подаренным разрешением.
- Реализация: Bot API шлёт сообщение → deep-link открывает мини-апп на нужном экране.

---

## 7. Чек-ин: enum ощущений

`feeling`: `zero_guilt` (😌 ноль вины) · `joy` (🎉 кайф) · `scared_but_good` (😬 страшно, но кайф) · `empty` (😐 пусто) · `guilt` (😔 накрыло виной).
Никогда не оценивается и не комментируется осуждающе. Просто пишется. Питает паттерны (за MVP).

---

## 8. Карта освобождения / «Список да»

- **Домены-регионы:** Одежда, Отдых, Комфорт/дом, Здоровье, Удовольствия, Еда. Каждый `PermissionEvent` заливает свой регион.
- **Состояния региона:** `fogged` (ещё ни разу не разрешал тут) → `opened` (≥1) → `thriving` (≥ N, напр. 5).
- **Счёт свободы:** сумма `value` по всем событиям — подаётся как «ты вернул(а) себе на X», а не «потратил». То же число, обратный смысл.
- **Метрики (не тщеславные):** всего разрешений (count); счёт свободы (sum); доля `below_threshold` (мышца); тренд времени до разблокировки; «впервые» (первое событие в каждом домене — отмечаем особо).
- **Wrapped:** периодический/годовой итог как шар-картинка (за MVP, но заложить).
- Визуал — SVG/canvas с регионами и заливкой; данные уже есть, вся работа в картинке.

---

## 9. Шеринг (вирусный двигатель)

- **Карточка «Разрешено»:** картинка вещи + «Официально разрешено · afford.today». Рендер: server-side SVG→PNG (satori + resvg) или client canvas.
- Отдаём через Telegram share / prepared message API в чаты.
- Делятся не тратой, а тем, что **позволили себе** — это эмоционально и этично.
- Поверх — Affiliate Program Telegram (задаёшь % выручки рефереру).

---

## 10. Тон и тексты (примерные)

**Онбординг (3 экрана):**
1. «Ты много работаешь. А тратить на себя без вины — почему-то сложно.»
2. «afford.today — это твоё личное «можно». Добавь то, что хочешь, сделай пару шагов — и разреши себе.»
3. «Начнём с малого: позволь себе сегодня что-то крошечное. Прямо сейчас.» → создаёт первое микро-разрешение и сразу даёт «Можно!». *(правило 90 — облегчение в первой сессии)*

**Экран «Можно!»:** «Officially разрешено. Иди забирай 🎉» · «Ты заслужил. И вообще — ты и так достоин.» · «Купил без гринда? Вот это рост. Горжусь.»

**Пустые состояния:** вишлист — «Чего ты хочешь? Не «что полезно», а что *хочется*.» Карта — «Тут будет всё, что ты себе позволил. Пока пусто — но это ненадолго.»

**Первый paywall:** не «купи подписку», а «позволь себе помощь — это тоже забота о себе».

## 11. Монетизация (Telegram Stars)

- **Free (щедрый, ради виральности):** до 2 активных желаний, базовые шаги, «Можно!» + шеринг, базовая карта.
- **Подписка (недельная цена в приоритете):** безлимит желаний, полная карта + wrapped, курируемые паки микро-разрешений, умные пуши бота, темы для ритуала разблокировки. Апселл на месяц/год.
- **Разовые покупки за Stars:** премиум-анимации/темы «Можно!», доп. «подаренные разрешения», экспорт wrapped-постера.
- **Affiliate Program** — основной канал роста.
- ⚠️ **Сверься с актуальной Bot API / Payments докой** (`core.telegram.org/bots/payments`, `/bots/api`) перед интеграцией: Stars и подписки эволюционируют. Базовый флоу: `createInvoiceLink` (валюта `XTR`) → `pre_checkout_query` → `successful_payment` вебхук; для подписок — Star-subscriptions с тирами.

## 12. Интеграция с Telegram (для Dev)

- **Авторизация:** валидируй `initData` на бэкенде (HMAC по bot token). Никаких отдельных логинов — это и есть нулевое трение.
- **Хранилище:** всё состояние на бэкенде (server-authoritative). Telegram CloudStorage — только лёгкий несекретный кеш.
- **Парсинг ссылок:** при вставке URL товара — fetch OG-тегов на сервере (таймаут, лимиты, без хранения чужого контента).
- **Платежи:** Stars через Bot API (см. §11).
- **Шеринг:** share / prepared message API для карточки «Можно!».
- **Холодный старт = фича:** первый экран открывается мгновенно, онбординг лёгкий.

## 13. Стек (предложение под Claude Code)

- **Frontend:** React + `@telegram-apps/sdk` (или `telegram-web-app.js`), Tailwind, framer-motion (анимация «Можно!»).
- **Backend:** Node (Fastify) или Python (FastAPI). БД: Postgres (для MVP можно SQLite).
- **Бот:** grammY (Node) / aiogram (Python).
- **Картинки шеринга:** satori + @resvg/resvg-js (SVG→PNG) на сервере.
- HTTPS обязателен для мини-аппа.

## 14. Граничные случаи и правила

- Покупку **никогда** не блокируем; «уже купил» всегда доступен и празднуется.
- `essential` не гейтим вовсе.
- Архив/удаление цели в процессе — разрешено, без вины; очки просто обнуляются (в MVP).
- Валюта — на отображение; тиры порога в валюте пользователя.
- Стрик переименован в «дни на своей стороне»; пропуск — нейтрален.
- Никаких тёмных паттернов в paywall (таймеры, преднажатые согласия и т.п.).

## 15. Граница MVP

**В MVP:** вишлист (с парсингом ссылки) · типы essential/need/want · шаги + очки (фикс-тиры) · экран «Можно!» + шар-карточка (полируем сильнее всего) · чек-ин-реакция · базовая карта (count + счёт свободы + регионы) · дневной нудж бота · авторизация через initData.

**За MVP (заложить поля, не строить):** платежи/подписка (застабить) · тающий порог · wrapped · подаренные разрешения · детект паттернов из чек-инов · продвинутые состояния карты.

## 16. Порядок сборки

1. Каркас мини-аппа + auth по `initData` + модели User/Wish/Step.
2. Вишлист (создание, парсинг ссылки, типы, авто-порог).
3. Шаги + очки + шкала.
4. Экран «Можно!» (разблокировка + «уже купил» + `PermissionEvent`).
5. Шар-карточка + Telegram share.
6. Чек-ин-реакция.
7. Карта / Список да (регионы + счёт свободы).
8. Бот: дневной нудж + deep-link.
9. Полировка тона/текстов и пустых состояний.
10. (Потом) Stars, подписка, wrapped, тающий порог.
